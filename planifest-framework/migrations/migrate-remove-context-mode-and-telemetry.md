# Migration: remove the Context Mode and Telemetry MCP integrations

**Target:** a downstream project's installed Planifest hooks, its tool settings files, and leftover `plan/.telemetry-*` folders
**Scope:** files that `setup.sh` or `setup.ps1` installed, plus two runtime folders under `plan/`. This migration never edits `plan/_archive/`, `plan/changelog/`, or application code.
**Safe to skip:** Yes, if the project never installed Planifest with `--context-mode-mcp` or `--structured-telemetry-mcp`. Step 1 detects that and records the outcome.

---

## Background

Feature `0000030-context-mode-and-telemetry-mcp-removal` (framework version 0.29.0) removed both optional MCP integrations from Planifest. The decision is recorded as 0000030-ADR-002 in `docs/decisions-index.md`.

The framework no longer ships these files:
- `hooks/context-mode/`
- `hooks/telemetry/`
- `hooks/enforcement/check-telemetry-failures.mjs`, `check-telemetry-receipts.mjs`, and `phase-enum.mjs`
- `standards/telemetry-standards.md`

Skills no longer emit events, and build-log phase blocks no longer have a `Telemetry` field.

A project that installed either integration still has settings entries that run those hook files. Once the files are gone, each entry fails on every matching tool call. The hooks fail open, so nothing blocks, but every call prints a missing-module error.

From 0.29.0, setup cleans this up itself on every run (0000030-ADR-004). It still accepts `--context-mode-mcp`, `--structured-telemetry-mcp`, and `--backend-url`. Each one prints a one-line notice and has no effect (0000030-ADR-003).

---

## What This Migration Does

1. Detect stale state. For each tool folder the project uses (for example `.claude/`, `.cursor/`, `.windsurf/`, `.opencode/`), look for any of these:
   - a settings entry whose command runs a file under `hooks/context-mode/` or `hooks/telemetry/`
   - a settings entry that runs `hooks/enforcement/check-telemetry-failures.mjs` or `check-telemetry-receipts.mjs`
   - a hook group whose matcher is `mcp__structured-telemetry-mcp__emit_event`
   - a `hooks/context-mode/` or `hooks/telemetry/` folder
   - `.claude/telemetry-enabled`, `plan/.telemetry-failures/`, or `plan/.telemetry-receipts/`

   If none exist, report "No Context Mode or Telemetry install found. Nothing to migrate" and record the outcome (Step 5).
2. Confirm that `planifest-framework/component.yml` reports version `0.29.0` or later. If it's older, stop and tell the human on the loop to refresh `planifest-framework/` first. Setup from an older framework would reinstall the hooks.
3. Re-run setup for each tool the project uses, with the flags it normally uses. If you use `planifest-refresh-setup`, it rebuilds those flags for you. Setup removes every stale entry, folder, and file, and prints one line for each removal.
4. Check what setup could not do:
   - If setup reported a settings file that isn't valid JSON, it skipped the clean-up for that file. Fix the JSON, then re-run setup.
   - If setup warned that Node is missing, it skipped the clean-up. Install Node, then re-run setup.
   - If the project's boot file (`CLAUDE.md`, `AGENTS.md`, or similar) isn't regenerated by setup, remove any `emit-phase-start / emit-phase-end` line from it by hand.
5. Record the outcome.

Hand-added hooks are safe. Setup removes only entries whose command points at a removed Planifest hook path.

---

## Present Findings

Report to the human on the loop:
- each tool folder checked, and what stale state it had
- each entry, folder, or file that setup removed
- anything left for a person to fix (malformed JSON, missing Node, a boot file to edit by hand)

---

## Record

Once the human on the loop confirms the findings, the migrator records the outcome at `plan/_migrations/migrate-remove-context-mode-and-telemetry.md`. This file stays where it is.
