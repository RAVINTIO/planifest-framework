## Findings (severity-ordered)

- [critical] `requirements/req-002-skill-drift-check.md` FR-002.3: the source `planifest-framework/skills/planifest-orchestrator/SKILL.md` starts with a UTF-8 BOM (bytes `ef bb bf`, verified). `setup.sh:77` copies it with `cp`, so the installed copy keeps the BOM. The rule strips one BOM from the installed copy only, so the rewritten source still holds one and the bytes never match. The script then reports `stale: claude-code: planifest-orchestrator` on every install, and on a PowerShell 7 install as well. req-001 FR-001.5 step 3 expects exit 0, so the 0.34.0 migration can't complete in this repo, and AC-002.1 ("exits 0 when all match") fails. Fix: strip one leading BOM from both texts before comparing. Add a FR-002.6 fixture whose source `SKILL.md` holds a BOM, and a suite case that runs the check against this repo after setup. The `design.md` drift-check decision states the same installed-only rule, so the orchestrator should raise that line with the human on the loop.
- [major] `requirements/req-001-rerun-setup-migration.md` FR-001.1, FR-001.2, FR-001.3, and FR-001.6: the definition counts a template or standard as setup-delivered only when a skill names it in `bundle_templates` or `bundle_standards`. `setup.sh:111-124` copies every template when the key is absent or empty. Six skills omit `bundle_templates`, and three set it to `[]`. The orchestrator's key also goes unread, because its BOM defeats the `awk '/^---$/'` frontmatter parse. The installed orchestrator therefore carries every template, `build-log.template.md` and `product.template.yml` included. As a result, the FR-001.2 table misses `templates/product.template.yml`, which changed between `2253e80` and `5c7859a`. FR-001.3 also cites the build-log template as manifest-bundled when no skill names it. FR-001.6 then writes the narrow definition into the update policy. Fix: define a setup-delivered template or standard as any file setup copies, including the copy-all fallback. Add `product.template.yml` to FR-001.2, and have the suite or the P3 diff step derive the list from setup's real behaviour.
- [major] `risk-register.md` A-001 and R-012, and `feature-brief.md` Constraints and Assumptions: A-001 and the brief both say setup copies each `SKILL.md` byte for byte. R-012's mitigation says "Compare raw bytes". `design.md` Assumptions, `execution-plan.md` A-001, and req-002 FR-002.3 all say setup rewrites four paths and may add a BOM. Fix: update A-001 and R-012 to the rewrite-and-strip rule. Replace "the check warns only" with an action, such as the suite case that runs the check on this repo. Correct or annotate the brief's assumption.
