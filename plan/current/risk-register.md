# Risk Register - 0000039-ravintio-rebrand

**Skill:** [spec-agent](../../planifest-framework/skills/spec-agent-SKILL.md)
**Feature:** 0000039-ravintio-rebrand
**Version:** 0.1.0
**Overall Risk Level:** high

> Sources: `design.md` Risks, and the RAVINTIO Zero 0000160 build report and risk register.

## Risks

| ID | Category | Description | Likelihood | Impact | Mitigation | Status |
|----|----------|------------|------------|--------|-----------|--------|
| R-001 | technical | A split or built old name escapes the scripted replace. Suites build `plan` + `ifest` style literals from parts, so a text search misses them. RAVINTIO Zero 0000160 found four of these across two late cycles. | high | medium | P1 lists every split or built name before the pass. Each gets a test or a protected-list entry (req-005). The brand guard catches the rest (req-007). Search `main` for split literals before the pass. | open |
| R-002 | technical | A suite that reads history fails after the rename. Examples are a tag folder fixture, a byte fixture, and archive paths. RAVINTIO Zero 0000160 lost a cycle to four of these. | high | medium | P1 lists all 43 suites and marks each one that reads `plan/_archive/`, `plan/changelog/`, `plan/_migrations/`, or git history. The protected list covers those paths. Write a test for the protected list before the pass. | open |
| R-003 | operational | This run's own skills and hooks change name mid-run. After the pass, the `planifest-*` skills the orchestrator loads and the installed hooks no longer exist. The run could stop or resume on a missing skill. | high | high | The pass, the `setup.sh claude-code` re-run, and the build-log update land in one commit. The resume step in the build log names the new skill. Do not start the pass with other work uncommitted. | open |
| R-004 | technical | The PowerShell helper or `setup.ps1` fails to parse, or acts on a junction. RAVINTIO Zero 0000160 shipped a helper that never parsed, and a recursive delete that followed nested junctions on Windows PowerShell 5.1. `pwsh` is not installed locally. | medium | high | The helper never deletes. It moves the old pack to `.ravintio-backup/` and refuses links and junctions at every level. CI runs both PowerShell legs on a draft PR before review. Reuse the nested-link handling already in `setup.ps1`. | open |
| R-005 | technical | The pass damages the mojibake byte sequence in `setup.sh` or `setup.ps1`. A text replace that re-encodes the file turns those lines into different bytes. | medium | high | Run the replace with a byte-exact tool, per token, on a protected line list. Add a byte-comparison test for the mojibake lines before the pass (req-005). | open |
| R-006 | technical | Bash 3.2 on the macOS CI leg hides lines in a guard loop. `done < <(...)` behaves differently there, so the brand guard can pass locally and miss hits. RAVINTIO Zero 0000160 hit this in P3. | medium | medium | The guard and every new suite use `done <<< "$(...)"`. Run the guard and the allowlist test under Bash 3.2 and Bash 5 before the first push. | open |
| R-007 | operational | A consumer's branch protection requires the old check name. After the upgrade the workflow reports `RAVINTIO Strict Pipeline`, so merges wait on a check that never runs. | medium | low | The consumer migration warns the human on the loop to require the new name. The changelog entry repeats the warning. | open |
| R-008 | operational | The migrator orders pending migrations by file name. `migrate-0.37.0-ravintio-rename.md` sorts before named older ones such as `migrate-adoption-mode-and-about-md.md`. A consumer that still has those pending runs them after the pack folder moves, and their bodies name `planifest-framework/` paths (23 hits in shipped migration bodies). | medium | high | The bodies stay as written because they are history. Older pending migrations run against `ravintio-framework/` paths through the mapping in req-009. They never read `.ravintio-backup/`. Test the ordering with a fixture that holds a pending older migration. | open |
| R-009 | operational | Links to `github.com/RAVINTIO/ravintio-framework` fail until the human on the loop runs `gh repo rename`. The README, docs, and install steps point at a repo that does not exist yet. | high | low | The rename runs right after merge and updates `origin`. The PR description says so. GitHub redirects the old repo name once the rename runs. Deferred in `design.md`. | open |
| R-010 | operational | `gate-write` and `shell-write-guard` block writes during the pass. Enforcement paths change from `planifest-framework/` to `ravintio-framework/`, and the gate reads a link or `..` by text and by target. A blocked write mid-pass leaves a half-renamed tree. | medium | high | Run the pass only after P1 and the P2 design checks, so `plan/current/design.md` exists and the components are declared. The recorded exception to Hard Limit 8 covers the script. Run `setup.sh claude-code` in the same commit. If the pass stops, `git checkout` restores it because nothing is committed yet. | open |
| R-011 | operational | Installed consumer markers stay behind. `.planifest-session`, `.planifest-manifest`, `.planifest-setup-flags`, and old boot-file and ignore-file blocks confuse detection or appear twice next to the new ones. | medium | medium | The migration removes the old marker files. Setup replaces the old boot-file markers and ignore-file headers, and reads `.planifest-setup-flags` once before removing it. Tests check that each old marker is gone and no block appears twice (req-002, req-006). | open |
| R-012 | operational | A consumer runs the new `setup.sh` before the migration. The old and new pack folders then sit side by side. | medium | medium | Setup stops while `planifest-framework/` or `planifest-overrides/` exists and names the migration (req-002, which owns the stop, with the migration from req-006). | open |
| R-013 | compliance | A consumer's `PLANIFEST_*` setting loses effect silently. Only `PLANIFEST_SESSION_ID` has a read fallback, so every other renamed variable stops working with no warning. | medium | medium | The migration body lists each renamed variable (req-006). A test shows `RAVINTIO_SESSION_ID` wins and the old name works when the new one is unset (req-003). The 1.0.0 removal date is written down. | open |
| R-014 | technical | The brand guard blocks legitimate old names, or its allowlist grows wide enough to hide real misses. Candidates are the `planifest-docs` links, `plan/backlog/*/_reference/`, `external-skills/`, and the `C:\d\planifest\framework\` path. | medium | medium | Each entry has a path regex, a line regex, and a reason. A stale entry fails the suite. A second case plants the old name in a tracked file and expects failure (req-007). | open |
| R-015 | technical | The pass rewrites vendored upstream text under `external-skills/` (771 files), which breaks the upstream text and the skill drift check. | medium | medium | The protected list skips `external-skills/` and the pass changes only pack-authored lines. A test compares those files with their pre-pass bytes. | open |
| R-016 | operational | Renaming the 21 `planifest-*` skills leaves orphan skill folders in a consumer's installed tool directory, so old and new skills load together. | low | medium | Setup already prunes skills the pack no longer ships. Add a test that the old skill names go on the next setup run. | open |
| R-017 | operational | A consumer's installed `.github/workflows/planifest.yml` keeps calling `planifest-framework/` paths. Setup never overwrites it, so CI fails after the upgrade. | high | high | The helper renames the workflow to `ravintio.yml` and rewrites only the pack's own names in it. A fixture test uses a consumer workflow with custom steps and checks they survive. | open |
| R-018 | security | The helper follows a symbolic link or junction at `planifest-overrides/`, `.git/info/exclude`, or the pack folder, and moves or writes outside the consumer repo. | low | high | The helper refuses links and junctions before it moves anything. It never deletes, and a clash stops it before any move. The security review covers the helper (req-006). | open |
| R-019 | operational | The backup keeps a full old pack in the consumer repo until the human on the loop deletes it. It adds noise and could be committed by mistake. | medium | low | The helper writes `.ravintio-backup/` to the git exclude file and tells the human on the loop to delete it after a check. | accepted |
| R-020 | operational | The `setup.sh claude-code` re-run overwrites a hook wiring or `core.hooksPath` that still points at `planifest-framework/hooks`. Git then skips the hooks once the folder moves. | medium | high | Setup sets `core.hooksPath` to `ravintio-framework/hooks` on every run (req-008). The migration helper does not set it. A test checks the value after setup runs on a fixture that starts from an old 0.36.0 install with `core.hooksPath` set to `planifest-framework/hooks` (req-008 second criterion). | open |
| R-021 | technical | Git's 50% similarity threshold turns a small renamed file, such as `hooks/ravintio.yml` or the workflow, into `D` plus `A` once many brand tokens change. History then loses the rename link for that file. | medium | low | Dry-run the pass in a scratch clone and run `git diff -M --name-status` to confirm every listed path reports `R` (req-001). If a file falls below the threshold, log it in the build log and accept `D` plus `A` for that file only. | open |

Documented assumptions from the specification are logged here with likelihood: medium.

| ID | Assumption | Impact if Wrong | Status |
|----|-----------|----------------|--------|
| A-001 | Consumers set no `PLANIFEST_*` variable except `PLANIFEST_SESSION_ID`. | A consumer setting loses effect silently after upgrade. | open |
| A-002 | No consumer depends on the `@planifest` npm scope outside the OpenCode plugin path. | That consumer's plugin import breaks. | open |
| A-003 | The `planifest-docs` sibling repo keeps its name after the framework repo renames. | The allowlisted sibling links break and need a follow-up edit. | open |
