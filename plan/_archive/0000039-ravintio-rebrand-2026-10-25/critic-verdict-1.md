## Findings (severity-ordered)
- [critical] F1 req-006 (Functional Requirements step 2, AC2): the stop condition "`.ravintio-backup/planifest-framework` exists" is unconditional. After a completed run that backup always exists, so a rerun exits non-zero. This contradicts "a rerun changes nothing and exits 0" (AC2), "every step skips done work", and design.md consumer migration step 4 and the Scope Lock error and cross-session paths. Fix: stop on the backup only while `planifest-framework/` still exists.
- [major] F2 req-003 AC1 (also Functional Requirements inventory): the command excludes only `plan/_archive` and `plan/changelog`. The result will also hold `PLANIFEST_*` in shipped migration bodies, `plan/_migrations/`, `plan/current/`, backlog `_reference/`, `external-skills/`, and the req-006 helper, which must name the pack-owned variables it rewrites in a consumer workflow. AC1 ("returns only `PLANIFEST_SESSION_ID` and `PLANIFEST_TELEMETRY*`") fails as written. Align the exclusions with req-007 and name the helper's variables.
- [major] F3 risk-register R-008 vs req-009: R-008 says older migrations run "against `.ravintio-backup/planifest-framework/` or the new paths" and "the helper does not run until they finish". req-009 says the migrator never reads `.ravintio-backup/` as a live pack and the helper runs by hand first. Rewrite R-008.
- [major] F4 R-020 vs req-006 and req-008: R-020 says the migration sets `core.hooksPath` and a test checks it "after a run from an old install". req-006 steps 1 to 8 never set it. req-008 AC2 checks only a fresh fixture. Add the step and the old-install test, or correct R-020.
- [major] F5 The 0.37.0 version bump has no owning requirement or AC. `scope.md` points at req-006, which says nothing about it. Add the files that carry the version and an observable AC.
- [major] F6 req-006 and req-009 have no AC for the Scope Lock error path and cross-session path ("half-moved helper stops at the failed step, names it, finishes on re-run"). req-006 AC2 covers only a rerun after a complete run. Add a partial-state fixture. The fresh-consumer path (no old folders, migration skipped) has no AC either, since req-009 AC3 tests only this source repo. Also update the brief's "Scenario Paths".
- [major] F7 req-001 AC3 requires `R` entries for small files such as `hooks/planifest.yml` and the workflow. Git applies the 50% similarity threshold after the content replace, and a small file with many brand tokens can fall below it. The design allows one commit only. State a fallback or a test that proves each file stays above the threshold, and add a risk.
- [major] F8 NFR-003 measurement (execution-plan.md): use `git diff --diff-filter=MDR --name-only` or equivalent. The current form counts files that ship adds.
- [major] F9 req-007 "Allow only these cases" omits entries that other reqs say it covers: the two `test-0000030` `PLANIFEST_TELEMETRY*` files (req-003), the protected needles in `test-0000036-req-001` (req-005 section 2), the mojibake lines that cannot change (req-004), and the old-name fixtures in req-002 tests. Live backlog entries that quote the old name (0000237 and the entries filed during this feature) are also unlisted. Extend the closed list.
- [major] F10 req-006 split record (item 9): add `Split step: keep` with a named single concern to the file, or split AC3 and AC4. The AC4 PowerShell parity criterion is arguably a second concern.
- [minor] R-013 mitigation (changelog and variable list) has no requirement owner. Same for the upgrade steps that req-009 Fact 3 relies on.
